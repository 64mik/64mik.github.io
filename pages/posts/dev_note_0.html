개발 일지 #1

여러모로 시도해보고 싶은 것은 많은데 할게 많아서 시간이 모자란 것 같다.

다른 블로그, 뉴스 등을 참고하고자 봤는데, 대체로 콘텐츠 양 옆을 비우고

상,하단 바를 주로 사용하는 것 같았다. 왜 그런지 찾아보니, 글을 읽을 때,

사이드 바가 시선을 분산 시키고, 다른 글로 빠지게 해서 오래 붙잡기 힘들다는 것 같다.

변경하고 나서 확인해보니 사이드 바도 미감적으로 나쁘지 않았으나, 상단 바가 더

나은 것 같다. 시간이 부족하여 모바일 대응은 일단 후순위로 미뤄야 할 것 같다.

현재 빌더 구조가 ( 폴더 생성 -> md 파일 존재시 md 전체를 하나씩 for문으로 읽음

-> 읽은 md를 html로 filesystem을 이용해 만들어서 만들어져있는 폴더에 임시 저장 )

인데, 찾아보니, filesystem 과 cout는 I/O 바운드라는 것 때문에 병목이 심하다고 한다.

추후 시간이 된다면 STL 자료구조(ex: string, vector 등)을 포인터를 통해 구현하여

처리된 문자열 값을 배열에 쌓고 메모리 pool을 받아와서 재사용하는 구조로 변경하면

조금 더 좋은 성능을 기대할 수 있을 것 같다. 그렇다면 최대 힙 정렬을 통해 최신글을 반영하는

기능도 추가할 수 있을 것 같다. 다만, 실력 미숙으로 발생한 난잡한 코드들 부터 마저

리펙토링이 필요할 것 같다.
